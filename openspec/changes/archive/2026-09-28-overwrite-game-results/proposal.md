## Why

Повторный запуск завершается WinError 183: игровой JSON уже существует. Перезапись ранее включена только для диагностических отчётов; действующая спецификация прямо запрещает замену партий.

## What Changes

- **BREAKING**: игровой JSON по совпадающему целевому пути атомарно заменяется после успешной проверки новой партии.
- При ошибке распознавания, валидации или публикации прежний файл сохраняется; ошибка отражается в отчёте и коде завершения.
- В итоговой строке сбоя ` — ошибка` выводится после скорости: `  Обработано 99% за 101 сек скорость 2.84x — ошибка`.
- В интерактивном терминале отметка ошибки красная, после неё цвет сбрасывается; перенаправленный вывод остаётся без цветовых кодов. Если терминал не поддерживает цвет, сохраняется читаемый текст.
- Схема имён и каталог report остаются прежними. Файлы партий, для которых в новом запуске нет результата, автоматически не удаляются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `video-game-export`: разрешить безопасную замену игрового JSON при повторном экспорте.
- `video-processing-progress`: перенести отметку ошибки в конец итоговой строки после скорости.

## Impact

Дополнительно затрагиваются форматирование итоговой строки в domino_video/progress.py и tests/test_progress.py. Промежуточные названия этапов и расчёт скорости сохраняются.

Точка сохранения в domino_video/manager.py, комментарий хранилища, регрессионные тесты и README. Используется существующий ExportStorage.write(replace=True); новые зависимости и параметры не нужны. Совпадение полного имени означает замену, в том числе если содержимое исходного видео изменилось. Защита по хешу не добавляется.
