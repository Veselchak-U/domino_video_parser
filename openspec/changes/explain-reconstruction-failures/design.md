## Context

См. proposal.md. build проверяет фиксированный порядок событий; _round_options отклоняет ветви через continue без объяснения. Отсутствие решений сейчас обозначено «не удаётся однозначно восстановить края», а manager записывает время начала партии независимо от фактического места отказа.

## Goals / Non-Goals

Цель — наблюдаемая диагностика для последующего системного исправления. Изменение не чинит распознавание, не переупорядочивает события и не ослабляет проверки. Исследовательские контрфактические опыты не становятся кодом приложения.

## Decisions

- Reconstructor владеет краткоживущей трассой одного поиска. Чистые вспомогательные функции агрегируют причины и форматируют русские описания; они не читают видео и не влияют на выбор ветвей.
- Приватный _round_options принимает необязательный список для трассы; без него результат остаётся тем же. Существующий тестовый override расширяется этим параметром. Не вводится скрытое состояние реконструктора между видео.
- ReconstructionError переносит serializable diagnostic с code/round/event/time/details. Manager публикует его в games[].reconstruction_diagnostics, дублирует code в соответствующем errors[] и использует фактическое время. Неизвестное время остаётся null.
- Для каждого события сохраняются входное и выходное число состояний, причины и не более двух примеров на причину. Это ограничение представления, не порог распознавания. Трасса сохраняет предшествующие события как компактный контекст без полного набора состояний поиска; полные наблюдения уже есть в отчёте. Превышение числа примеров обозначается явно.
- Неизвестный исполнитель, предел руки 7, начальная рука, прежний пас, обязательность текущего паса, геометрия, несовместимость конца и счётчик получают отдельные коды. Обнаруженный start не на первом событии или другая определённая метка первого события записываются предупреждением и не исправляются автоматически.
- Top-level причины охватывают проверки build и итогового счёта. Отсутствие вариантов, несколько валидных вариантов и лимиты имеют разные коды. Примеры ошибок валидатора ограничиваются пятью, количество проверенных/отброшенных вариантов сохраняется.
- Диагностика встроена одинаково для CPU/GPU и любого числа процессов: этап реконструкции общий. Реальный GPU не заявляется проверенным без доступного DirectML.

## Risks / Trade-offs

- Большой отчёт → счётчики полные, примеры ограничены; не сохранять все состояния поиска.
- Побочные изменения решений при инструментировании → регрессия шести успешных JSON, сравнение статусов всех 16 записей и полный pytest.
- Принятие первой причины за корень ошибки → описывать конкретно отброшенные ветви; предупреждать в документации, что исходная причина может быть в более раннем чтении.
- Диагностика кандидатов после ручных исправлений → передавать через исключение именно проверявшиеся данные, не восстанавливать их из исходного отчёта.

## Verification

Пользователь явно поручил остановиться после добавления диагностики без прогонов и дальнейшего анализа причин. Регрессионные тесты добавляются без запуска; полная проверка и архивирование отложены. Это исключение из обычного порядка запуска падающего теста задано пользователем. Исправления алгоритма остаются отдельным будущим изменением.
