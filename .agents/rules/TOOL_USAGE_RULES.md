# Поиск, чтение и работа в Windows

## AST Index: структурный поиск кода

Подключён [AST Index](https://github.com/defendend/Claude-ast-index-search)
версии 3.55.0, локально через npm в tools/ast-index. Версия и пакеты закреплены
в package.json и package-lock.json этого каталога; это инструмент разработки,
а не зависимость Python-приложения.

Установка из корня проекта при отсутствии инструмента:

```powershell
npm.cmd ci --prefix tools/ast-index --cache .analysis/npm-cache
.\ast-index.cmd version
.\ast-index.cmd rebuild
```

Node.js/npm нужны для установки и npm-обёртки. Не переустанавливай CLI перед
каждой задачей. Версию обновляй отдельной правкой manifest/lock с проверкой CLI.
Сохраняй настройки доступности релизов npm; воспроизводимая установка идёт
из lock-файла. Не меняй глобальные настройки npm ради локального инструмента.

[Локальный запуск](../../ast-index.cmd) передаёт аргументы CLI, переключается
в корень этого checkout и задаёт AST_INDEX_CACHE_DIR внутри .analysis/.
Всегда используй эту обёртку на Windows, чтобы не создавать второй индекс
в глобальном кеше. На других ОС запускай локальный npm binary из корня,
задав AST_INDEX_CACHE_DIR в абсолютный путь .analysis/ast-index-cache.

[Конфигурация](../../.ast-index.yaml) индексирует domino_video, tests и tools,
исключает модели, фикстуры, зависимости, видео и результаты. Индекс и node_modules
игнорируются Git; .gitignore учитывается, --no-ignore обычно не нужен.
Не подключай соседние репозитории или другие worktree без отдельной задачи.

### Выбор запроса

Используй AST Index для неизвестной структуры, определений и связей символов.
Если нужный файл и диапазон уже известны, читай их напрямую без промежуточного
запроса к индексу. Выбирай команду по известным данным:

```powershell
.\ast-index.cmd explore "video export storage"
.\ast-index.cmd class ParseManager
.\ast-index.cmd symbol main --in-file 'domino_video\cli.py'
.\ast-index.cmd refs ParseManager
.\ast-index.cmd usages ParseManager
.\ast-index.cmd callers main
.\ast-index.cmd outline domino_video/manager.py
.\ast-index.cmd imports domino_video/manager.py
.\ast-index.cmd --format json class ParseManager
```

explore — вопрос или описание задачи; search/symbol/class — известное имя;
refs объединяет определения, импорты и использования. Не повторяй успешный
структурный запрос через rg только «для полноты». Читай найденные участки кода
для проверки смысла, а не загружай все найденные файлы целиком.

В JSON проверяй pagination.truncated (у refs/search — для каждого набора).
Обрезанный ответ не полный: увеличь --limit или сузь --in-file/--module.
На Windows --in-file сопоставляет путь из результата индекса с обратными
слешами; при пустом ответе проверь написание пути. Команда outline принимает
и обычный путь с прямыми слешами.
Статический индекс не доказывает отсутствие динамических Python-вызовов:
при конкретном подозрении проверь getattr, реестры или строки отдельно.
Найденные ссылки не объявляй автоматически семантическими доказательствами.

### Актуальность и чтение

- Первый запуск или отсутствующий индекс: rebuild, затем stats.
- После группы правок исходников/тестов и после pull/rebase/checkout/switch:
  update до следующего структурного запроса. Не обновляй после каждой строки
  и после правки только Markdown, если индексируемые исходники не менялись.
- После изменения конфигурации, состава корней или явно неконсистентного индекса:
  rebuild. Каждый worktree имеет свой индекс; не объединяй их.
- Watcher необязателен. Не запускай долгоживущие watch или фоновые hooks
  автоматически; обычный update после группы правок достаточен для этого проекта.
- Для незнакомого большого исходного файла используй outline, чтобы выбрать
  нужный символ или диапазон. Размер файла сам по себе не требует outline,
  если нужный участок уже известен. Для Markdown/JSON и других неиндексируемых форматов
  выбирай разделы через rg и частичное чтение.

При отсутствии CLI/индекса, ошибке или пустом результате используй rg как
запасной путь и сообщи ограничение, если оно влияет на вывод. Не делай циклы
rebuild ради пустого поиска; сначала проверь stats, корень и include/exclude.
При разрешённом делегировании передавай агенту эти правила, путь обёртки и
требование актуального индекса; само наличие инструмента не требует делегирования.

## Текстовый поиск

Для строковых литералов, регулярных выражений, содержимого комментариев,
документации и неиндексируемых файлов используй ripgrep:

```sh
rg --files domino_video tests
rg -n 'Не удалось|needs_review' domino_video
rg -n 'score-limit' README.md
rg -n -g 'test_*.py' 'timeout|shutdown' tests
rg --files --hidden .agents tools
```

Проверь определение и реальные использования символа. Текстовое совпадение
может быть комментарием или одноимённым символом. Маски передавай через -g
и существующий каталог: в PowerShell путь tests/test_*.py не раскрывается
для rg как список файлов.

Если rg недоступен, используй Get-ChildItem и Select-String.
Не предполагай наличие других индексов или фоновых сервисов.

## Чтение и вывод

- Сначала найди нужные разделы; большие файлы читай частями.
- Не загружай зависимости, сборочные каталоги и весь архив OpenSpec без причины.
- Уже прочитанный неизменившийся файл используй повторно. Перечитай его после
  изменения, при признаках внешней правки или утрате контекста.
- После редактирования просмотри изменённый участок или diff.
- Независимые чтения и проверки объединяй; зависимые операции выполняй по порядку.
- Большие ответы инструментов сокращай до нужных полей перед выводом.
  Обрезанный обязательный текст дочитывай; не выдавай обрезанную историю за полную.

## Windows и окружение

Команды Python выполняй в виртуальной среде, на Windows всегда с UTF-8:

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest -q tests/test_storage.py
.venv/Scripts/python.exe -X utf8 -m domino_video --help
```

То же требование действует для -c, временных скриптов и stdin.
На POSIX используй .venv/bin/python. Bash-скрипты запускай в Bash.
Проверяй код завершения каждой значимой команды: успешная последняя команда
не доказывает успех предыдущей. Не смешивай файловые удаления и перемещения
между оболочками; работай с проверенными явными путями.

Установку зависимостей повторяй при изменении среды или зависимостей.
Не выполняй дорогую диагностику окружения для каждой правки.
