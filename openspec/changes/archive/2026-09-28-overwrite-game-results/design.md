## Context

Причина описана в proposal.md. ExportStorage уже поддерживает атомарную замену через os.replace, но ParseManager включает её только для отчётов.

## Goals / Non-Goals

Цель: повторный экспорт без конфликта существующего файла. Автоматическое удаление лишних старых партий и транзакция на всё видео не входят в изменение.

## Decisions

Цвет ограничить суффиксом ошибки через ANSI SGR с восстановлением цвета текста. На Windows включать обработку VT для настоящего консольного дескриптора через SetConsoleMode; при недоступности использовать обычный текст. При перенаправлении не включать цвет. Учёт ширины строки должен учитывать только видимые символы, чтобы очистка предыдущего статуса не зависела от ANSI-кодов.

Итог ошибки в ConsoleProgress.finish формировать из обычного статуса без этапа и суффикса ` — ошибка` после скорости. Это сохраняет порядок промежуточных этапов и не требует распознавать текст ошибки в общем форматтере. Для интерактивного и перенаправленного вывода проверить точную итоговую строку, отсутствие 100% и сохранение последней скорости при ошибке или прерывании.

Передавать replace=True при сохранении проверенной партии. Сохранить существующую сериализацию во временный файл в том же каталоге, fsync и очистку в finally. Удаление старого файла перед записью отвергнуто: при сбое оно теряет прежний результат. Базовый режим хранилища без замены остаётся доступным; поправить комментарий о его назначении.

Регрессионный тест ParseManager повторяет экспорт по одному пути и проверяет актуальное содержимое, успешный отчёт, код 0 и 100%. Отдельно проверить отказ os.replace и невалидную новую партию: старое содержимое сохранено, нет временных файлов, код 1. Использовать существующие фикстуры распознанных наблюдений, чтобы изолировать файловую ошибку от OCR.

## Risks / Trade-offs

Совпадение имён разных источников между запусками → замена определяется полным целевым путём, что явно описано в proposal. Недоступный или заблокированный файл → понятная ошибка, сохранение старого результата. Старые лишние партии → сохраняются, актуальный состав указан в отчёте текущего запуска.

## Проверка реализации

Регрессия до исправления: 10 падающих тестов (повторный экспорт, порядок и цвет ошибки), 23 успешных. После исправления полный набор: 164 passed in 37.11s. Ruff check и format --check: успешно, 26 файлов. В реальном Windows PTY подтверждены TTY=True, COLOR=True, красный суффикс после скорости и обычный текст после него. Тесты повторного экспорта используют сохранённые наблюдения контрольного видео и сравнивают полный игровой JSON с эталоном; OCR повторно не запускался, его код не менялся. Проверены отказ атомарной замены, невалидный результат, сохранение дополнительных старых партий, отсутствие временных файлов, сброс цвета и очистка длинной строки. Строгая валидация OpenSpec успешна.
