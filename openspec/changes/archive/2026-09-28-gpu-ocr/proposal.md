## Why

На контрольном видео основная стоимость распознавания приходится на OCR. На машине есть GTX 1060 3 ГБ, но текущий ONNX Runtime использует CPU; нужно подключить GPU и измерить реальный выигрыш без потери точности.

## What Changes

- Добавить `--device auto|cpu|gpu`, по умолчанию auto. Первый GPU backend — DirectML на Windows.
- Подтверждать доступность GPU запуском моделей, показывать реально выбранный режим. Auto при неуспешной инициализации выбирает CPU с причиной; принудительный gpu выдаёт ошибку.
- Оставить обработку изображений на CPU, выполнять OCR одним экземпляром моделей на GPU с ограниченной очередью.
- Подготовить воспроизводимую установку GPU в отдельном окружении, не изменяя рабочую CPU-среду до проверки. Драйвер и системный CUDA не устанавливать.
- Сравнить полное время, память и итоговый JSON на контрольном видео. Ускорение заранее не обещается.

## Матрица режимов

| Режим | GPU успешно инициализирован | GPU отсутствует, ОС не поддерживается или инициализация неуспешна |
|---|---|---|
| auto | GPU OCR, CPU для остальных операций | CPU с однократной причиной выбора |
| cpu | CPU, GPU не инициализируется | CPU |
| gpu | GPU OCR, CPU для остальных операций | Код 1, русская диагностика до обработки видео |

Ошибка GPU после начала распознавания завершает текущий источник с отчётом и кодом 1 без ложного успеха. Следующий источник заново проверяет GPU; auto может выбрать CPU. Автоматический повтор текущего видео не добавляется.

## Ответственности

| Компонент | Владеет состоянием | Читает/пишет | Выполняет | Явно не выполняет |
|---|---|---|---|---|
| OCR adapter | Модели и выбранный provider | Только модели и OCR crops | Инициализацию, проверку provider, OCR | Экспорт, реконструкцию, прогресс |
| ScreenRecognizer | CPU-алгоритмы | Кадры, наблюдения | Геометрию, подготовку областей, разбор OCR текста | GPU lifecycle, файловый экспорт |
| ObservationPipeline | Очереди и порядок кадров | Ограниченный поток заданий | CPU-пул и единственную последовательную GPU-очередь, сбор результатов | Правила игры и запись файлов |
| ParseManager | Обработка источника | Входы, отчёты через прежние компоненты | Выбор режима и координацию | Вычисления OCR и геометрии |

CPU-пул принадлежит pipeline. GPU-модели создаются и вызываются в одном выделенном потоке pipeline, не сериализуются между процессами. Все очереди завершаются при выходе из источника, ошибке и прерывании.

## Capabilities

### New Capabilities

- `gpu-ocr`: выбор вычислителя OCR, диагностика, совместимость и проверка результата.

### Modified Capabilities

- `video-processing-progress`: параллельность CPU и последовательный GPU OCR с ограниченной памятью.

## Impact

CLI, manager, pipeline, vision, отдельный OCR adapter, установка и run.bat, документация и тесты. Правила домино, формат игровых JSON, даты файлов и механизм атомарной записи не меняются. CUDA, аппаратное декодирование видео, несколько GPU и автоматический выбор самого быстрого адаптера вне объёма первой версии. Используется адаптер DirectML 0; ограничение явно описывается в README.
