## Context

ConsoleProgress сейчас перерисовывается из основного потока при изменении процента.
Вызов распознавания или записи может занимать больше секунды. Мотивация — в proposal.md.

## Goals / Non-Goals

Обновлять прошедшее время независимо от поступления результатов кадров.
Сохранить обработку кадров и JSON; предварительное хеширование пакета остаётся до start.

## Decisions

- Монотонные часы передаются зависимостью; время — int(elapsed) с новым началом
  для каждого файла. Системные часы не подходят из-за возможного перевода времени.
- ConsoleProgress владеет одним потоком таймера только для интерактивного вывода.
  Поток ждёт следующую секундную границу через Event.wait, без активного ожидания.
  Основной поток передаёт последний процент и этап; таймер отображает их раз в секунду.
  Один callback после кадра не подходит: ожидание результата может быть долгим.
- start немедленно печатает 0% за 0 сек. finish останавливает таймер и немедленно
  отображает итог. Время берётся при завершении, до ожидания остановки таймера.
- Процент, этап и запись в stdout защищены одной блокировкой. message завершает
  текущую строку и печатает сообщение под той же блокировкой; таймер не смешивает
  символы сообщения и прогресса. Имя файла выводится один раз полностью.
- finish/закрытие устанавливает Event и присоединяет поток вне блокировки.
  ParseManager гарантирует очистку в finally при успехе, ошибке и прерывании;
  после финального статуса таймер больше не пишет. Следующий файл получает новый отсчёт.
- В перенаправленном выводе поток не создаётся: остаются начало, итог и диагностика.
- Тесты используют управляемые часы и события синхронизации, без произвольных пауз.

- Для отчёта использовать явный параметр replace при записи ExportStorage и
  os.replace временного файла из того же каталога после flush/fsync. Игровые JSON
  сохраняют os.link с отказом при существующем файле. При ошибке публикации старый
  отчёт сохраняется, временный файл удаляется.

## Risks / Trade-offs

Конкурентная запись → общий lock; остановка без deadlock → join вне lock.
Долгая операция → отдельный таймер обновляет строку с последним известным процентом.
Планировщик ОС может задержать отдельное обновление; пропущенные секунды не печатаются
очередью задним числом, следующее обновление показывает актуальное время.

## Проверка реализации

Полный набор: 146 тестов прошли (32,79 с). Ruff и проверка форматирования пройдены.
Проверены реальные потоки таймера с синхронизацией по выводу, неизменный процент,
ожидание декодирования и записи отчёта, целые секунды, сброс отсчёта,
перенаправление и отсутствие оставшихся потоков после успеха/ошибки/прерывания.
Проверены замена существующего отчёта, сохранение старого при отказе публикации
и удаление временного файла. Воспроизведён исходный отказ до исправления.
Повторный полный прогон видео не требовался: распознавание кадров не менялось.
