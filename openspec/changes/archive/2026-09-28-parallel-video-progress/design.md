## Context

ParseManager._observe декодирует и распознаёт кадры в одном цикле; каждые 20 секунд
печатает timestamp. RapidOCR использует два intra/inter-потока. VideoReader отдаёт
кадры с PTS, но не длительность. __main__.py выполняет main при импорте без guard.
Обоснование изменения и ответственность компонентов — в proposal.md.

## Goals / Non-Goals

Ускорять тяжёлое распознавание одного видео, сохраняя прежние выбор кадров, OCR
каждые пять секунд, dense score OCR и реконструкцию. Не делить видео на независимые
куски партии и не выполнять конкурентную запись итогов.

## Decisions

- ObservationPipeline использует ProcessPoolExecutor со spawn и initializer,
  создающим собственный ScreenRecognizer каждого worker. Кадр, PTS и read_text
  вычисляются родителем; worker возвращает только Observation. Такой обмен
  сохраняет прежнее расписание OCR независимо от скорости worker.
- Одновременно держать не более 2*N отправленных/готовых кадров; извлекать
  результаты в порядке отправки. Процент вычислять по последнему принятому
  наблюдению, не по последнему декодированному кадру. Отдельный поток для печати не нужен.
- OpenCV и intra/inter OCR в worker используют по одному потоку. Декодер тоже
  ограничивается, чтобы каждый worker не пытался использовать все CPU одновременно.
  Последовательный режим использует тот же распознаватель с согласованными настройками.
- CLI выбирает доступный CPU count через process_cpu_count при наличии, затем
  sched_getaffinity при наличии, затем os.cpu_count; неизвестное число даёт 1.
  На Windows применяется максимум ProcessPoolExecutor 61. Можно явно уменьшить N.
- Метаданные длительности брать в секундах из видеопотока (duration*time_base),
  затем контейнера. Если их нет, дополнительный проход получает диапазон PTS.
  Проценты учитывают начальный PTS; пустой/непригодный диапазон диагностируется.
- ConsoleProgress принимает поток, обновляет строку при изменении целого процента
  без дробей и повторов того же значения через возврат каретки и очистку хвоста пробелами. Имя с номером
  печатается полностью один раз отдельной строкой, прогресс — ниже в формате
  `  Обработано N%` с двумя начальными пробелами. Длинное имя
  может переноситься терминалом; возврат каретки затрагивает только прогресс.
  Перед обычным сообщением завершает строку прогресса. При non-TTY только
  старт и итог. Во время хеширования допустима фаза 0%, без секунд.
- Завершение pipeline отменяет не начатые задания и закрывает executor. При
  BrokenProcessPool источник завершается ошибкой; следующий создаёт новый пул.
  Interrupt обрабатывается родителем, ресурсы закрываются в finally. Guard
  `if __name__ == '__main__'` обязателен для модульного запуска на Windows.

## Risks / Trade-offs

- 24 модели OCR требуют заметной памяти → ограниченная очередь, --workers 1/N,
  документирование расхода; не объявлять OOM успешным завершением.
- Передача кадров между процессами стоит времени → сравнить реальный прогон
  образца на 1 и автоматическом N; не обещать ускорение без измерения.
- Предварительный проход при неизвестной длительности → дополнительное чтение,
  но корректный процент без выдуманного знаменателя.
- Различный порядок завершения → упорядоченный сбор и сравнение полного JSON.

## Migration Plan

После согласования — падающие тесты, компоненты, интеграция и CLI, проверки на
Windows и образце, README. Новые параметры необязательны; старые игровые параметры,
дата имён и каталог вывода сохраняются. Для диагностики доступен --workers 1.
