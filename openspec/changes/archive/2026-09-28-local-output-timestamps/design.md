## Context

RecordingTimeResolver использует astimezone(timezone.utc) и добавляет Z для
aware-метаданных и текущего времени. Запрос меняет только это преобразование.

## Goals / Non-Goals

Использовать локальную таймзону машины запуска без отдельной настройки приложения.
Сохранить источники времени и точность. Не мигрировать ранее созданные файлы.

## Decisions

- Для aware-времени использовать datetime.astimezone() без аргумента: ОС определяет
  локальное смещение для конкретной даты. Не фиксировать сегодняшнее смещение
  для всех дат, поскольку оно может отличаться при сезонном переводе часов.
- Подстановку часов преобразовывать тем же способом перед форматированием.
  Удалить Z из обоих форматов. Даты без пояса и из имени не преобразовывать.
- Для детерминированных тестов внедрить узкое преобразование времени как callable
  с реализацией astimezone() по умолчанию; это не публичная настройка CLI.
  Проверять UTC+03, UTC, смену календарной даты и текущие миллисекунды.
- В отчёте original для метаданных остаётся исходным значением, в prefix хранится
  локальное имя. Поле original подстановки может содержать смещение: запрет Z
  относится к именам файлов, а не к диагностическим ISO-значениям.

## Risks / Trade-offs

- Перенос между машинами с разными зонами меняет имя → документировать, что зона
  берётся из ОС; старые выходы не переименовывать.
- Неизвестный пояс исходной даты → считать её локальной, не выдумывать смещение.
- Совпадение локального времени при переводе часов → прежние номера и запрет перезаписи.
