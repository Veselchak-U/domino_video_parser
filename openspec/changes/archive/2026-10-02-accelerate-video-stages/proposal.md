## Why

Декодирование ограничено одним CPU-потоком, дополнительный анализ камней последовательный, а адресный OCR заново открывает видео для каждого кадра. Эти ограничения мешают использовать доступные CPU и GPU.

## What Changes

- В auto/gpu пробовать аппаратное декодирование CUDA; при недоступности использовать многопоточный CPU с объяснением. Auto сравнивает скорость коротких проб CPU/GPU и выбирает GPU только при выигрыше; gpu принудительно использует доступный GPU-декодер. CPU не инициализирует GPU.
- Распространить выбранное число CPU-процессов на дополнительный анализ движущихся камней без OCR.
- Читать запрошенные OCR-кадры одним декодером с сохранением точных PTS и экономией повторных seek.
- Сохранить алгоритм распознавания камней, расписание OCR, порядок, ограниченность очередей и игровые JSON.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `video-processing-progress`: ускоренное декодирование и параллельность всех проходов.

## Impact

VideoReader, ObservationPipeline, ParseManager, справка CLI, README и тесты. Новых зависимостей нет; PyAV уже содержит аппаратный декодер. Политика DirectML OCR и активное изменение retry-gpu-workers-by-total-memory остаются самостоятельными.
