# Правила коммитов

По умолчанию оставляй выполненные изменения незакоммиченными. Запрос реализовать,
исправить, проверить или завершить задачу сам по себе не разрешает коммит.
Создавай коммит только по явному запросу пользователя; не выполняй автоматически
git add, commit или amend при завершении работы. Push требует явного запроса
на публикацию; разрешение коммита само по себе его не разрешает.

При явном запросе коммита оформляй текущие согласованные изменения одним коммитом.
Спецификации, код, тесты, документация и связанные правила проекта могут входить
в один коммит. Обязательного разделения по категориям или порядка категорий нет.
Разделяй изменения на несколько коммитов только по просьбе пользователя.

Порядок разработки — по [правилам OpenSpec](OPENSPEC_RULES.md);
он не задаёт структуру истории Git.

## Проверка перед публикацией

- Сообщение коммита понятно описывает включённые изменения.
- Итоговый diff проверен; в нём нет случайных файлов, секретов или временных результатов.
- Выполнены применимые проверки кода, тестов и спецификаций.
- Согласованные изменения пользователя сохранены.
- Указания пользователя о числе коммитов и публикации соблюдены.
