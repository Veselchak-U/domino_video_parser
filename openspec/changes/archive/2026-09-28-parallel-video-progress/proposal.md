## Why

Пользователь хочет видеть процент обработки в одной строке без количества секунд
и задействовать все доступные ядра CPU. Сейчас кадры обрабатываются последовательно,
OCR ограничен двумя потоками; прогресс печатается отдельными строками раз в 20 секунд.

## What Changes

- Имя и номер источника выводить один раз: `[2/5] полное_имя.mp4`.
  Процент обновлять отдельной строкой ниже: `  Обработано 10%`, с двумя пробелами
  в начале и без обработанных секунд.
  Финальный статус и сообщения об ошибках/сохранении остаются читаемыми отдельными строками.
- Процент растёт по завершённому распознаванию кадров; 100% показывается только
  после завершения проверок и записи всех результатов источника без ошибок.
- Добавить `--workers N`: положительное число процессов распознавания; по умолчанию
  число доступных логических процессоров (с платформенным ограничением Windows 61).
  `--workers 1` обеспечивает последовательный режим.
- Параллельно распознавать кадры одного видео, собирать наблюдения в исходном порядке.
  Источники пакета остаются последовательными, формат и содержание JSON сохраняются.
- Ограничить очередь кадров и внутренние потоки библиотек, освобождать процессы при
  окончании, ошибке и прерывании. Не обещать линейного ускорения или постоянных 100% CPU.

## Capabilities

### New Capabilities

- `video-processing-progress`: процентный прогресс и параллельное распознавание кадров.

### Modified Capabilities

Нет: существующие правила обработки, входы/выходы и порядок источников сохраняются.

## Матрица режимов

| workers | Обработка |
|---|---|
| Не задан | Доступные логические CPU, минимум 1; на Windows максимум 61 |
| 1 | Последовательно без дочернего пула |
| 2..платформенный максимум | Пул указанного размера |
| 0, отрицательное, дробное, выше максимума Windows | Ошибка аргументов, код 2 |

| Длительность | Консоль |
|---|---|
| Известна | Обновление 0..99%, затем 100% при успехе |
| Неизвестна | Та же строка 0% с фазой определения длительности; предварительный проход, затем обычный процент |
| Невозможно получить корректные временные отметки | Ошибка источника, без ложных 100% |

При перенаправлении вывода печатать старт/итог без управляющих возвратов каретки
и без сотен промежуточных строк. В интерактивной консоли — одна обновляемая строка прогресса под именем.

## Ответственности

| Компонент | Владеет состоянием | Читает/пишет | Выполняет | Явно не выполняет |
|---|---|---|---|---|
| VideoReader | Открытый контейнер | Видео, длительность, кадры | Декодирование и выбор кадров | OCR и консоль |
| ObservationPipeline | Пул и ограниченная очередь | Кадры и наблюдения | Распараллеливание и восстановление порядка | Начисления, JSON |
| ScreenRecognizer в worker | Собственная модель OCR | Кадр | Распознавание | Общая консоль, очередь ходов |
| ConsoleProgress | Последний процент/длина строки | stdout | Отрисовка прогресса | Декодирование, файлы |
| ParseManager | Источник/результаты | Pipeline, progress, storage | Порядок этапов | Планирование процессов и отрисовка |

Пул принадлежит pipeline одного источника и закрывается до перехода к следующему.
Дочерние процессы не пишут результаты или прогресс. Очередность событий принадлежит pipeline,
а игровая реконструкция выполняется прежним компонентом в родительском процессе.

## Impact

CLI, manager, video, vision, защищённая точка входа __main__, новые pipeline/progress,
тесты и README. Использовать стандартный concurrent.futures, без новой зависимости.
На этой машине обнаружено 24 логических CPU. Несколько OCR-моделей требуют больше
памяти; пользователь может уменьшить --workers. GPU и параллельная запись файлов вне объёма.
