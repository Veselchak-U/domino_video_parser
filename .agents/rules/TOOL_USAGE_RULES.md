# Поиск и чтение ресурсов проекта

## Поиск

Для текстового поиска и списка файлов используй ripgrep:

```sh
rg --files lib test
rg -n 'class |enum |typedef ' lib
rg -n 'MyApp' lib test
rg --files --hidden .agents tools
```

При поиске символа проверь определение и все найденные использования. Текстовые
совпадения могут включать комментарии и одноимённые символы; не считай их
автоматически семантическими ссылками.

Если ripgrep недоступен, используй стандартные средства оболочки, например
Get-ChildItem и Select-String в PowerShell. Не предполагай наличие дополнительных
индексов, серверов языка, плагинов или фоновых обработчиков.

## Чтение файлов

- Сначала найди файл и нужные разделы, затем читай относящиеся к задаче фрагменты.
- Большие файлы читай частями; наличие файла не требует загрузки его целиком.
- После изменений перечитай затронутый участок.
- Не обходи каталоги сборки и зависимостей без конкретной необходимости.
- Поиск ограничивай проектом; внешние ресурсы должны быть общедоступными и относиться к задаче.

## Проверка ссылок

Относительные Markdown-ссылки разрешаются от каталога документа.
Команды разработки в документации предполагают корень проекта, если явно не
указано другое. Перед добавлением ссылки проверь существование локального
ресурса либо доступность публичного адреса.

Отличай путь существующего ресурса от шаблона будущего выходного файла.
Шаблоны допустимы только с явным указанием, что файл создаётся в рамках задачи.
Не описывай несуществующие файлы, скиллы и утилиты как готовые зависимости.
