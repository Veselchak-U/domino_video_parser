## Context

ParseManager сейчас строит prefix из индекса и path.stem. В образце имя содержит
2026-09-28-13-58-19, а creation_time контейнера и видеопотока —
2026-09-28T11:05:07.000000Z. Поэтому источник даты должен иметь явный приоритет.
ExportStorage уже запрещает перезапись. Формат игрового JSON изменять не требуется.

## Goals / Non-Goals

Изолировать выбор времени от распознавания и начислений. Не использовать дату
файловой системы и не угадывать локальный пояс записи. Не переименовывать прошлые результаты.

## Decisions

- Новый RecordingTimeResolver получает Path, возвращает неизменяемую структуру
  с основой имени, исходным значением и источником. Manager получает его через
  необязательную зависимость с рабочей реализацией по умолчанию.
- Регулярное выражение выделяет кандидатов только из path.stem; datetime проверяет
  календарные значения. Несколько разных минут — отказ; повторы одной допустимы.
  Анализ каталогов исключён, чтобы дата папки не подменяла дату записи.
- Если имя дало результат, файл ради метаданных не открывается. Иначе PyAV открывает
  контейнер в with, читает creation_time контейнера и первого видеопотока, закрывается
  до основного декодирования. Некорректное значение контейнера допускает переход к потоку.
- Метаданные разбираются через datetime.fromisoformat после проверки наличия даты
  и времени до минут; Z обрабатывается как UTC. Основа aware-времени нормализуется
  в UTC и получает Z; naive-время не локализуется автоматически.
- Prefix состоит из времени и source-NNN; суффиксы game-NNN/report сохраняют
  привычную структуру. Только при неоднозначном имени остаётся undated-source-NNN
  для диагностики. При отсутствии даты или ошибке чтения метаданных используется
  текущее UTC-время до миллисекунд, полученное один раз на источник через
  внедряемые часы. Миллисекунды усекаются из микросекунд, дополняются до трёх цифр.
  В отчёте source=current_time и причина подстановки; ошибка декодирования видео
  по-прежнему не превращается в успешный экспорт.
  Индекс обеспечивает уникальность внутри пакета, а прежняя атомарная запись —
  защиту от конфликта между запусками. Новые суффиксы при конфликте не выдумываются.
- Тесты manager с синтетическими байтами получают явно заданную дату через resolver
  или имя. Сам resolver проверяется отдельно, включая настоящий маленький контейнер
  с метаданными и чтение метаданных предоставленного образца.

## Risks / Trade-offs

- Creation_time может быть временем обработки файла → имя имеет приоритет,
  в отчёте сохраняется точное происхождение даты, не обещается физическая точность метаданных.
- Подстановка не является временем записи → явно отражать current_time и причину в отчёте.
- Минутная точность даёт совпадения → номера источников и партий, запрет перезаписи.
- Неизвестный пояс → сохранять naive-время, не привязывать результат к настройке ОС.
