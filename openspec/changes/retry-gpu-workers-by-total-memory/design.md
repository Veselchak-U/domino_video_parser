## Context

См. proposal.md. DeviceOCR сейчас допускает максимум два процесса по свободной памяти NVIDIA; GPUWorker уже изолирует модели через spawn и ограничивает время инициализации. Небольшие искусственные тензоры текущей пробы не отражают рабочие размеры OCR. CLI --device gpu сейчас завершает запуск ошибкой при недоступности GPU; новая политика намеренно меняет это.

## Goals / Non-Goals

Goals: конечная последовательность попыток по общему объёму, ограниченное ожидание, отсутствие оставшихся процессов, прежний формат результатов и строки прогресса.

Non-Goals: автоматический повтор видео при сбое в середине, настройка числа по скорости, очистка чужой VRAM, CUDA, дополнительные адаптеры, гарантия 100% загрузки GPU.

## Decisions

1. Читать DedicatedVideoMemory из DXGI описания адаптера 0, переводить байты в MiB. Это уже используемый путь выбора карты, не требует nvidia-smi и работает независимо от производителя. SharedSystemMemory не добавлять. Ошибка/нулевой объём означает неизвестную память и одну попытку. Свободная память больше не нужна ни для допуска, ни для проверки группы.
2. Бюджет 1024 MiB определяет только начальную верхнюю оценку. Для положительного объёма меньше 1024 всё равно пробовать один. Явные --gpu-workers 1/2 сохраняют смысл верхнего ограничения. Расширение числовых значений CLI вне объёма этого изменения.
3. DeviceOCR владеет группой. Создание процессов последовательное для понятной диагностики. После загрузки всей группы подать пробу всем процессам, затем дождаться всех результатов с ограничением 60 сек на пробную фазу. Проба выполняет все модели и полный OCR на фиксированном изображении с текстом в размерах рабочего профиля; вход и ожидаемые признаки успешного распознавания фиксируются тестом. Маленькую текущую проверку моделей сохранить при загрузке. Рабочая проба снижает вероятность позднего отказа, но не гарантирует покрытие пиков на любом видео.
4. При любой ошибке группы остановить все её процессы, включая частично созданный, затем N−1 с чистого состояния. Не сохранять первый процесс от неудачной группы: его состояние после нехватки памяти нельзя считать проверенным. Правила завершения GPUWorker сохраняются (5 сек мягко, затем принудительно). KeyboardInterrupt/SystemExit не превращать в повтор или CPU.
5. При отсутствии DirectML не создавать заведомо нерабочие группы. Auto/gpu переходят на CPU с причиной. Проверка установки в ocr.main должна отдельно проверять enabled и возвращать ошибку при CPU, чтобы не печатать ложное «GPU verified».
6. Сообщения попыток печатать до progress.ready(); часы по-прежнему включают инициализацию. Размеры очередей обработки по CPU workers и порядок кадров не менять. Повторять выбор на каждом источнике.

## Risks / Trade-offs

- Избыток процессов может замедлить GPU и расходовать RAM → показать фактическое число, сохранить ручной предел 1/2, измерить полный запуск; не обещать ускорения.
- WDDM может вытеснять память и позволить перегруженной группе пройти пробу → считать это успешным запуском согласно выбранной политике; замерить скорость, не вводить скрытый порог свободной памяти.
- Несколько неудачных попыток увеличивают время старта → ограничить каждую загрузку и пробу 60 сек, объяснять попытки в консоли.
- Повреждение состояния драйвера после OOM → новые процессы для каждой попытки; CPU после исчерпания; драйвер не сбрасывать.

## Migration Plan

Через падающие тесты заменить чтение памяти и алгоритм выбора, добавить групповую пробу и обновить документацию/проверку установки. Выполнить полный набор тестов и реальную обработку контрольного видео с проверкой JSON и отсутствия оставшихся GPU-процессов. Откат — восстановление предыдущего алгоритма и спецификации отдельным изменением; миграция данных не требуется.
