## Why

Контрольное видео обрабатывается одним GPU-обработчиком за 100,1 сек, двумя изолированными процессами — за 75,0 сек при одинаковом JSON. Средняя загрузка GPU растёт с 54% до 76%; потоковый вариант с двумя комплектами моделей аварийно завершился. Пик общей видеопамяти двух процессов достигает 2822 MiB на карте 3072 MiB.

## What Changes

- Выполнять GPU OCR в одном или двух отдельных процессах с собственными моделями; автоматически выбирать два при подтверждённом запасе памяти.
- Добавить --gpu-workers auto|1|2 (по умолчанию auto). Значение 2 — верхняя желаемая граница с той же проверкой памяти; значение 1 запрещает второй процесс. --workers сохраняет значение числа CPU-работников.
- Определять свободную выделенную память для выбранного DirectML-адаптера 0. На NVIDIA использовать nvidia-smi только после однозначного сопоставления с DXGI. При неизвестной памяти, включая неподдержанную телеметрию AMD/Intel, сохранять один GPU-процесс с объяснением.
- При неуспешном запуске второго процесса продолжать первым; число и причина выбора видны в консоли. Во время обработки сохранять прежние правила ошибки источника, без скрытого повторного распознавания.
- Сохранить порядок наблюдений, ограничения очередей и полный JSON. Постоянные 100% GPU не гарантируются.
- Убрать отдельную промежуточную строку 0% перед сообщением OCR: показывать обновляемую строку после выбора backend, сохраняя в elapsed и скорости всё время с вывода имени файла.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `gpu-ocr`: адаптивное число изолированных GPU-процессов, CLI, память и диагностика.
- `video-processing-progress`: несколько GPU-владельцев при сохранении порядка и общей ограниченной очереди; отложенный показ прогресса до сообщения OCR.

## Impact

ocr.py, отдельные модули GPU-процессов и телеметрии, pipeline.py, cli.py, manager.py, setup_gpu.ps1, README, тесты. Новых Python-зависимостей не требуется. CPU-режим и контракты игровых JSON не меняются.

### Матрица выбора

| Режим | GPU недоступен | GPU доступен, память неизвестна/недостаточна | Памяти достаточно |
|---|---|---|---|
| device=cpu, любые gpu-workers | CPU без GPU-пробы | CPU без GPU-пробы | CPU без GPU-пробы |
| device=auto, gpu-workers=auto/2 | CPU с причиной | Один GPU-процесс | Два; при неудаче второго один |
| device=gpu, gpu-workers=auto/2 | Ошибка источника | Один GPU-процесс | Два; при неудаче второго один |
| device=auto, gpu-workers=1 | CPU с причиной | Один GPU-процесс | Один GPU-процесс |
| device=gpu, gpu-workers=1 | Ошибка источника | Один GPU-процесс | Один GPU-процесс |

### Ответственность

| Компонент | Владеет состоянием | Читает/пишет | Выполняет | Явно не выполняет |
|---|---|---|---|---|
| GPU memory probe | Только снимок памяти | DXGI, nvidia-smi | Сопоставление адаптера, проверка данных | Загрузка моделей, выбор числа процессов |
| DeviceOCR | Жизненный цикл и очереди GPU-процессов | Снимки памяти, готовность и результаты | Выбор 1/2, запуск, распределение, остановка | Декодирование, реконструкция, экспорт |
| GPU worker | Один комплект моделей | Подготовленные области, наблюдение | Проба моделей и последовательный OCR | Другие GPU-сессии, пользовательский вывод |
| ObservationPipeline | Общая очередь и порядок кадров | CPU/GPU futures | Ограничение 2*N/32*N, выдача по порядку | Выбор числа GPU-процессов |
