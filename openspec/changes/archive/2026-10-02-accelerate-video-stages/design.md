## Context

См. proposal.md. На контрольной машине 24 CPU и GTX 1060 3 GB. PyAV 18.1.0 успешно декодирует исходный кадр через CUDA; OpenCV 5.0 не собран с CUDA. OpenCL доступен, но полный алгоритм включает findContours, connectedComponentsWithStats, NumPy-медианы и Python-проверки отдельных контуров. Перенос только цветовых преобразований требует обмена CPU/GPU и не переносит эти этапы целиком.

## Goals / Non-Goals

Цель — GPU-декодирование там, где оно работает, и параллельная CPU-обработка остальных вычислений во всех проходах. Не меняются пороги распознавания и политика OCR DirectML. Не устанавливаются драйверы и новая CUDA-сборка OpenCV; активный change по памяти OCR независим.

## Decisions

- VideoReader владеет настройками и результатом пробы декодера для текущего источника. Проба открывает аппаратный контейнер с запрещённым скрытым software fallback, декодирует первый кадр и проверяет is_hwaccel. До выдачи кадров отказ допускает CPU; ошибки дальнейшего декодирования идут наверх. Каждый генератор владеет своим контейнером и закрывает его через with. Только один декодер выдаёт изображения в ограниченную очередь.
- GPU-кадры остаются на устройстве до выборки. Только выбранные кадры скачиваются и преобразуются через исходный software pixel format: прямое NV12→BGR меняет интерполяцию хромы относительно yuv420p→BGR и результат OCR. Проверено на контрольном кадре: 484322 различающихся компонент до исправления, 0 после.
- Замер на полном видео выявил: CPU 31,8 с, CUDA+DirectML 50,9 с после устранения лишних копирований. Поэтому auto сравнивает первые 120 кадров обоими декодерами с выборкой 2 кадра/с и выбирает быстрее. 120 — ограниченный предварительно выбранный размер пробы, около 4 с исходного видео при 30 fps, не гарантия оптимальности для всего файла. gpu сохраняет принудительный выбор исправного CUDA. Пробы выполняются последовательно до основного прохода, включают открытие и преобразование выбранных кадров, не загружают OCR. Проигравший декодер закрывается.
- CPU использует thread_type=AUTO и thread_count по workers; это разрешает кадровую параллельность, в отличие от прежнего thread_count=1. В CPU-workers OpenCV и OCR остаются однопоточными, предотвращая вложенные пулы.
- ObservationPipeline получает отдельный режим дополнительного анализа. Один top-level worker вызывает prepare(..., False, read_motion=True), возвращает только observation с dense=True, не инициализирует OCR. Пул, порядок и ограничения 2*N/32*N переиспользуются.
- Адресное чтение использует один контейнер на упорядоченный набор PTS. Близкие запросы декодируются последовательно; при промежутке больше секунды выполняется seek. Секунда — предварительная оценка компромисса, не требование PyAV; корректность PTS от порога не зависит. Результаты сразу уходят в существующий CPU/GPU OCR pipeline.
- Manager владеет последовательностью проходов, передаёт настройки созданному им reader, интегрирует результаты после полного чтения. Внедрённые тестовые reader сохраняют собственный жизненный цикл.

## Risks / Trade-offs

- Различия аппаратного декодера → сравнение PTS/пикселей и полного игрового результата на реальном видео.
- CUDA недоступна на других GPU → явный CPU fallback с параллельным декодером. DirectML OCR может работать независимо от CUDA-декодера.
- Накладные расходы spawn и передачи изображений → замер полного видео до/после на одинаковом workers=24; не обещать 100% загрузки.
- Память декодера и OCR на 3 GB → декодеры предыдущих проходов закрываются перед OCR; во время адресного чтения работает только один декодер совместно с OCR. Дополнительный проход не загружает OCR.

## Матрица

| Режим | CUDA работает | CUDA недоступна | CPU-анализ |
|---|---|---|---|
| cpu | GPU не пробуется | GPU не пробуется | workers процессов, декодер workers потоков |
| auto | GPU при более быстрой пробе, иначе CPU | CPU с причиной | workers процессов, включая дополнительные кадры |
| gpu | GPU-декодер | CPU с причиной | workers процессов, включая дополнительные кадры |

OCR следует прежним правилам --device и --gpu-workers. При workers=1 CPU-пул не создаётся во всех строках.

## Migration Plan

Новые зависимости и миграция данных не нужны. --device cpu отключает аппаратное декодирование; --workers 1 оставляет последовательный диагностический режим.
