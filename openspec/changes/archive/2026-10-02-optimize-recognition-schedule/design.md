## Context

См. proposal.md. Сейчас OCR запускается по общему флагу каждые 5 секунд; счёт также читается на пустом столе. Камни выбираются 4 раза/с. Финальная таблица наблюдается после последнего кона, за его end.

## Goals / Non-Goals

Уменьшить число OCR-вызовов, сохраняя игровую проверку и адресный анализ. Частоту, способы OCR, пороги имён и модели пользователь не просил делать параметрами CLI.

## Decisions

Два этапа: визуальный проход 2 кадра/с без OCR и адресный OCR полей на отобранных фактических PTS. Визуальные процессы не загружают OCR-модели. Адресный проход сохраняет существующий DeviceOCR и ограниченный ObservationPipeline, для CPU/GPU используются одинаковые запросы полей.

| Компонент | Ответственность |
|---|---|
| VideoReader | Выборка 2 кадра/с, native PTS, извлечение точного кадра |
| ScreenRecognizer/Profile | Дешёвая идентификация финальных карточек, геометрия областей, подготовка только запрошенных полей |
| Планировщик чтения полей | Объединение запросов по timestamp: финальные имена, послеконовые счёты, спорные счётчики |
| ParseManager | Порядок проходов, применение OCR к наблюдениям, прежняя проверка/публикация |
| GameReconstructor | Руки, события, адресная анимация, правила и использование повторных счётчиков |

Имена: несколько пригодных кадров финальной таблицы, карточки слева направо соответствуют местам 1,3,2,4. Область имени сохраняется в попытке и используется при PNG. При отсутствии таблицы назначаются Unrecognized_N; ручные исправления приоритетны. Интервал выбора имён заканчивается до начала следующей партии, а не на конце последнего кона.

Счёт: несколько кадров между раскрытием и следующим коном, включая позднее обновление анимированного табло. Запросы не распространяются на ходы. Счётчики: повторные кадры между спорным ходом и следующим, без имён/счёта. Значения закрытой руки не выводятся из её количества. Несколько кандидатов исполнителя и конфликт индикатора являются достаточным основанием адресного чтения.

Геометрические пороги детекции финальных карточек — эвристики данного профиля, проверяемые на оригинальных кадрах, поворотах и масштабах. Бюджет чтения фиксирует несколько кадров имён и ограниченные повторы для счёта/счётчиков; недостаточность доказательств сохраняет прежнюю ошибку. Изменение 2 кадра/с задано пользователем; плотный проход анимации сохраняет native FPS.

Конкретный бюджет: первые три кадра финальных карточек, последние три пригодных кадра итогового табло, первые два кадра внутри спорного хода с отступами 0,3 секунды от его границ. Финальные имена ищутся до конца записи либо начала следующего кона, без ограничения задержки появления таблицы. Области карточек и HSV-порог зелёного подобраны по предоставленному видео; полосы между карточками отличают таблицу от непрерывного игрового стола. Это эвристики текущего профиля, не универсальные пороги.

При 2 кадрах/с повтор ошибочного значения нового камня может совпадать с уже сыгранным. Контуры с дублирующими значениями становятся кандидатами позднего чтения: исключаются одноимённые якоря и требуется подтверждение после сдвига цепочки. Повторные короткие чтения на старом месте запрашивают native-анализ. После перерыва видимости анимации доказательством служит только последний непрерывный трек: прежний минимум трёх кадров, ограничения промежутков, удержание на столе и проверка правил сохраняются. Счётчики участвуют при нескольких кандидатах исполнителя, даже без общего конфликта индикатора; ошибочная одиночная цифра не решает ход.

Матрица CPU/GPU × один/несколько процессов: одинаковые запросы полей и результаты, различается устройство OCR; при отсутствии GPU применяется прежний fallback. При отсутствии финальной таблицы OCR имён N/A и генерируются неизвестные имена.

## Risks / Trade-offs

Редкая выборка пропускает короткие ходы → адресная анимация и регрессии на полном видео. Финальные имена могут быть обрезаны лентами карточек → сохранять только прочитанное, маски/диагностика и исправления. Несколько партий → ограничение финальных попыток своим интервалом. Сокращение OCR не гарантирует ускорения на любом GPU → замер одного запуска до/после без одновременной тяжёлой нагрузки.
