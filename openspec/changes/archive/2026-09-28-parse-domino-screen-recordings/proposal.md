## Why

Нужен воспроизводимый перевод записей домино в журнал игроков, раздач, ходов и результатов без ручного переписывания партии. Формат `kozel-game-v1` требует полной истории и проверки игровых правил, поэтому одного чтения табло недостаточно.

## What Changes

- Консольное приложение Python для одного или нескольких видео; каждый файл обрабатывается независимо, каждая завершённая партия сохраняется отдельным JSON.
- Первый поддерживаемый визуальный профиль — мобильная игра из предоставленного образца: зелёный стол, четыре игрока, светлые камни с точками, раскрытие остатков после кона. Масштабирование и поворот записи поддерживаются.
- Локальное распознавание через PyAV, OpenCV и OCR. Платные API и отправка видео во внешние сервисы не требуются.
- Восстановление начальных рук из ходов и раскрытых остатков, отслеживание очереди, краёв цепочки, пасов и границ конов.
- Проверка результата JSON Schema и полным воспроизведением по правилам из предоставленного репозитория. Неоднозначные или неполные партии дают отдельный диагностический отчёт с таймкодами; неподтверждённый итоговый журнал не создаётся.
- Необязательный файл исправлений позволяет уточнять распознанные имена, руки и ходы с повторной полной проверкой.
- Параметры `fishVariant` и `scoreLimit` обязательны. Предусмотрено явное задание имён и состава команд при нечитаемом тексте.

## Capabilities

### New Capabilities

- `video-game-export`: пакетное распознавание записей, восстановление и проверка партий, экспорт и диагностика.

### Modified Capabilities

Нет. В текущем каталоге до подготовки изменения были только AGENTS.md и .agents; приложение, тесты и основные спецификации отсутствуют, несмотря на описание Flutter в AGENTS.md.

## Impact

Новые Python CLI, тесты pytest, зависимости PyAV/OpenCV/локальный OCR/jsonschema, руководство запуска. Снимок внешнего контракта с хешами будет включён в проект при реализации; исходный репозиторий спецификаций не изменяется. Dart/Flutter не используются: пользователь разрешил выбрать стек.

Источники: `C:/Projects/Home/domino_spec/docs/formats/README.md`, `kozel-game.schema.json`, `kozel-game.example.json` в том же каталоге и `openspec/changes/add-kozel-fish-variants/specs/kozel-rules/spec.md`. Последний является планом правил, прямо указанным документацией формата, а не существующим игровым движком.

## Матрица поведения

| Вариант | Лимит 50 | Лимит 101 |
|---|---|---|
| withEggs | Рыба с переносом при равных остатках, завершение от 50 | То же, завершение от 101 |
| withoutEggs | При рыбе штрафуются обе команды, завершение от 50 | То же, завершение от 101 |

| Источник / результат восстановления | Поведение |
|---|---|
| Поддерживаемый профиль, полная однозначная партия | Проверка и JSON партии |
| Несколько полных партий в файле | По JSON на каждую |
| Обрыв, скрытые остатки, неоднозначность, конфликт правил | Отчёт с таймкодами; нет JSON проблемной партии |
| Исправления предоставлены | Повторное восстановление и те же проверки |
| Повреждённый файл / другой интерфейс | Понятная ошибка источника; остальные входы обрабатываются |

## Ответственности

| Компонент | Владеет состоянием | Читает/пишет | Выполняет | Явно не выполняет |
|---|---|---|---|---|
| VideoReader | Декодер одного файла | Видео | Кадры с временными метками | OCR, правила, экспорт |
| ScreenRecognizer | Неизменяемый профиль и OCR-модель | Кадры | Наблюдения камней, текста, индикаторов | Начисления и запись файлов |
| GameReconstructor | История наблюдений одной партии | Наблюдения и исправления | Связь кадров, руки, события, неоднозначности | Декодирование, начисления, файловый вывод |
| GameValidator | Состояние одного воспроизведения | Кандидат журнала | Законность, начисления, сравнение результатов | OCR и сохранение |
| ExportStorage | Нет игрового состояния | Выходные файлы | Атомарная запись JSON/отчётов | Распознавание и правила |
| ParseManager | Текущий источник и статус пакета | Делегирует компонентам | Последовательность этапов | Вычислительные алгоритмы |

Источники обрабатываются последовательно. CLI создаёт компоненты; VideoReader закрывается после каждого файла даже при ошибке, состояние партии сбрасывается на её границе, OCR загружается один раз на запуск. Конкурентной записи нет.

## Вне объёма

Съёмка настоящего стола, произвольные другие игры и темы, восстановление навсегда скрытых данных догадками, обучение нейросети, веб-интерфейс, объединение разрезанной партии из нескольких файлов, изменение внешнего JSON-формата. Неполная партия остаётся диагностикой, а не документом `kozel-game-v1`.
