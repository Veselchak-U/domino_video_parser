# Написание Python-кода

Стек и зависимости — [pyproject.toml](../../pyproject.toml).
Архитектура — [правила ревью](REVIEW_RULES.md).

## Перед правкой

- Прочитай затрагиваемый код, тесты и связанные спецификации.
- Для изменения поведения соблюдай [OpenSpec](OPENSPEC_RULES.md).
- Найди определение и реальные места использования по [правилам поиска](TOOL_USAGE_RULES.md).
- Следуй существующей структуре; не создавай слои и зависимости ради шаблона.

## Реализация

- Чистые функции подходят для вычислений и преобразований; классы нужны для
  состояния, ресурсов или явных зависимостей. Не вводи класс только ради теста.
- Внешние данные проверяй на входе: обязательность, неизвестные значения,
  числовые границы и ошибки формата.
- Не изменяй полученные коллекции без явного контракта; при необходимости копируй.
- Optional используй для реального отсутствия значения с обработанным путём.
- Типизируй новые публичные контракты и сложные границы; не размечай весь проект
  заодно. Не публикуй API только ради доступа теста.
- Сериализацию, OCR, файловый ввод-вывод и игровую логику разделяй по ответственности.
- Файлы именуй в snake_case, функции и классы — по смыслу; обязательных суффиксов нет.
- Ресурсы закрывай через контекстные менеджеры или finally. У процессов, потоков
  и очередей должны быть владелец, ограничение ёмкости и порядок завершения.
- Не вводи миграции и совместимость с ещё не использовавшимися форматами.
- Причины эвристик и ограничения фиксируй по [правилам ревью](REVIEW_RULES.md).

## Проверки

Форматируй только изменённые Python-файлы. Ruff check и format --check выполняй
по затронутым путям во время работы; перед завершением изменения кода проверь
domino_video и tests, если Ruff доступен. Исправления --fix применяй только после
просмотра к согласованному набору файлов; не форматируй весь проект с записью.

```powershell
.venv/Scripts/python.exe -X utf8 -m ruff check domino_video tests
.venv/Scripts/python.exe -X utf8 -m ruff format --check domino_video tests
```

Объём тестов, проверок OCR, CLI, пакета и видео выбирай по
[правилам тестирования](UNIT_TEST_RULES.md). Повторные проверки уже проверенного
состояния не нужны. Для документации проверяй текст, ссылки и согласованность;
для исполняемого скрипта — синтаксис и затронутые успешные/ошибочные ветки.

Перед завершением проверь итоговый diff. Укажи реальные результаты проверок
и непроверенные области; сохрани чужие изменения.
