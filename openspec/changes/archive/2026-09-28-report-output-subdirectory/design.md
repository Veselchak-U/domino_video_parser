## Context

ParseManager задаёт путь отчёта, ExportStorage уже создаёт родительские каталоги
и атомарно заменяет отчёты. Мотивация и матрица режимов — в proposal.md.

## Goals / Non-Goals

Изменить только каталог диагностического отчёта, включая отчёты об ошибках.
Сохранить алгоритм имён и не переносить ранее созданные пользовательские файлы.

## Decisions

Использовать output / report / имя отчёта в существующем вызове записи.
Сохранить replace=True и текущую обработку OSError. Новые компоненты не нужны.

## Risks / Trade-offs

Файл вместо каталога report → существующая обработка ошибки записи, код 1.
Старые отчёты останутся в корне → описать это поведение в README.

## Проверка реализации

148 тестов прошли через стандартный скрипт проекта. Ruff и форматирование прошли.
Проверены автоматическое создание подпапки, замена отчёта, сохранность старого
отчёта в корне, ошибка при файле вместо каталога, новые пути при запуске CLI,
BAT и EXE, включая отчёты по повреждённым видео и неоднозначной дате.
