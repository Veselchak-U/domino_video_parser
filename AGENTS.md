# Контекст проекта

Всегда отвечай пользователю на русском языке.

## Обязательные правила и старт сессии

В начале новой сессии первым обращением к инструментам прочитай с диска этот
AGENTS.md и [порядок применения правил](.agents/rules/_PRIORITY_RULES.md).
До соответствующего действия читай только применимые подробные правила
по навигации ниже. Делай это автоматически, без запроса разрешения.
Допустимо предварительное короткое сообщение о начале чтения.

- Явный запрос реализовать разрешает подготовку плана и реализацию в его рамках.
  Спрашивай о существенной неоднозначности или расширении объёма; запрос только
  на планирование не разрешает реализацию.
- До изменения поведения прочитай связанные спецификации, код и тесты.
  Сохраняй порядок: спецификация → падающий тест → реализация → зелёный тест.
- Во время разработки запускай затронутые тесты; полный pytest — на завершённом
  состоянии изменения приложения. Повтор нужен при изменении общей логики или
  перед завершением после новых изменений кода/тестов, а не из-за коммита или push.
- Проверяй JSON, игровые правила и сохранность файлов применительно к задаче.
  Не подменяй проверку реального OCR тестом с подменами.
- Обычные исправимые ошибки устраняй автономно; не сужай заказанное поведение
  ради успешных проверок. Существенный выбор поведения вынеси пользователю.
- В отчёте различай план, реализацию и фактически проверенный результат.
  Сохраняй чужие изменения и проверяй итоговый diff.

Обрезанный вывод дочитывай. Подтверждай чтение только после получения текста;
о недоступном файле сообщи явно. Повторно читай файл после изменения, при
признаках внешней правки либо утрате содержания из контекста. Не перечитывай
неизменившийся файл перед каждым шагом.

## Текущее состояние

Это консольное Python-приложение для локального разбора записей домино.
Точка входа — [domino_video/cli.py](domino_video/cli.py), параметры Python,
зависимости и настройки проверок — [pyproject.toml](pyproject.toml).
Стек выбран в изменении parse-domino-screen-recordings.
Тесты находятся в tests/ и запускаются pytest. Стиль проверяется Ruff.
Для структурного поиска кода подключён AST Index 3.55.0. На Windows используй
`.\ast-index.cmd` из корня проекта; установка,
обновление индекса и выбор между AST Index и rg — в
[правилах инструментов](.agents/rules/TOOL_USAGE_RULES.md).

## OpenSpec

Основные спецификации описывают текущее поведение; артефакты активного изменения —
план будущего поведения. Архитектурные решения фиксируй в артефактах изменения.
Перед правкой изучи относящиеся к ней спецификации и код. Если спецификаций
ещё нет, укажи это, не придумывай действующий контракт.

Сначала подготовь изменение поведения, затем реализуй его через падающий тест.
Запрос на реализацию уже разрешает оба этапа; дополнительное согласование нужно
для существенного выбора сверх запроса. Для документации и обслуживания
инструментов без изменения поведения приложения отдельный change не требуется.

## Команды разработки

Из корня проекта на Windows:

```powershell
.venv/Scripts/python.exe -X utf8 -m pip install -e ".[test]"
.venv/Scripts/python.exe -X utf8 -m pytest -q
.venv/Scripts/python.exe -X utf8 -m domino_video --help
.venv/Scripts/python.exe -X utf8 -m ruff check domino_video tests
.venv/Scripts/python.exe -X utf8 -m ruff format --check domino_video tests
openspec validate --all --strict
```

Команды Python выполняй в .venv, на Windows с -X utf8; на POSIX используй
.venv/bin/python. Установку выполняй при подготовке среды или изменении зависимостей,
а не перед каждой задачей. Ruff запускай, если он установлен в среде; наличие
конфигурации не означает наличие инструмента. Установка описана в [README.md](README.md).

Bash-скрипты запускай в Bash; на Windows можно использовать Git Bash.
Они сами переходят в корень проекта:

```sh
bash tools/tests/run_unit_tests.sh -q
bash tools/ai/run_openspec_validation.sh
```

Скрипт тестов передаёт аргументы pytest для выбора тестов; без выбора запускает
весь набор. Скрипты OpenSpec требуют установленный CLI и ripgrep.
