# Порядок применения правил проекта

Проектные правила уточняют общие рекомендации для этого репозитория.
Они не отменяют системные ограничения, разрешения среды и явные указания пользователя.

При выборе между проектными и общими рекомендациями используй такой порядок:

1. Правила из этого каталога.
2. [Контекст проекта](../../AGENTS.md).
3. Применимые скиллы из [каталога проекта](../skills/).
4. Общие рекомендации, если проектные источники не определяют решение.

## Перед задачей

При старте каждой новой сессии выполни обязательное чтение с диска по разделу
«Обязательный старт новой сессии» в [AGENTS.md](../../AGENTS.md): до первого
содержательного ответа и выполнения задачи прочитай контекст проекта и все
правила этого каталога. Не жди отдельного указания пользователя. Применяй только требования,
относящиеся к текущей работе; отсутствие неприменимого инструмента не блокирует задачу.

- Изменение поведения — [правила OpenSpec](OPENSPEC_RULES.md).
- Написание кода — [чеклист](CODE_WRITING_RULES.md).
- Архитектура и проверка решения — [правила ревью](REVIEW_RULES.md).
- Тесты — [правила тестирования](UNIT_TEST_RULES.md).
- Поиск — [правила инструментов](TOOL_USAGE_RULES.md).
- Итоговая история Git — [структура коммитов](COMMIT_STRUCTURE_RULES.md).

Скиллы выбирай из фактически существующих файлов. Не требуй отсутствующие скиллы,
автоматические проверки или внешние сервисы. Список доступных проектных скиллов
находится в контексте проекта.

При противоречии между кодом, текущими спецификациями и планом явно покажи
расхождение. Существенный выбор поведения согласуй с пользователем.
