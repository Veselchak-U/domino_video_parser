## Why

Пользователь хочет находить результаты по дате и времени записи, а не по длинному
исходному имени видео.

## What Changes

- **BREAKING:** имена журналов — `YYYY-MM-DD-HH-MM-source-001-game-001.json`,
  отчётов — `YYYY-MM-DD-HH-MM-source-001-report.json`. Номера сохраняют различимость
  нескольких источников с одинаковым временем и нескольких партий одного видео.
- Приоритет: валидная дата-время вида `2026-09-28-13-58` в имени файла (без пути),
  затем `creation_time` контейнера, затем первого видеопотока. Точность имени — минуты.
- Время из имени сохраняется без пересчёта часового пояса. Метаданные с часовым
  поясом переводятся в UTC, а дата в выходном имени получает суффикс `Z`.
  Метаданные без пояса сохраняются как записаны, без суффикса.
- Если даты нет или метаданные невозможно прочитать, подставлять текущее UTC-время
  один раз на источник: `YYYY-MM-DD-HH-MM-SS-mmmZ`. Экспорт продолжается;
  причина подстановки сохраняется в отчёте. Файловое mtime не используется.
- В отчёте фиксировать исходное значение даты, источник и выбранную временную основу.
  Существующие результаты не переименовывать и не перезаписывать.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `video-game-export`: имена файлов по времени записи и диагностика отсутствия даты.

## Матрица выбора даты

| Имя файла | Метаданные | Результат |
|---|---|---|
| Одна валидная дата | Любые | Время из имени |
| Нет валидной даты | Валидное creation_time | Время из метаданных |
| Нет валидной даты | Нет валидного creation_time | Текущее UTC-время с миллисекундами |
| Несколько различных валидных дат | Любые | Неоднозначность, отчёт об ошибке, код 1 |

Повтор одной и той же минуты в имени не создаёт неоднозначность. Некорректные
календарные даты не являются валидными кандидатами. Для метаданных применяется
приоритет контейнера над первым видеопотоком; остальные видеопотоки не используются.

## Ответственности

| Компонент | Владеет состоянием | Читает/пишет | Выполняет | Явно не выполняет |
|---|---|---|---|---|
| RecordingTimeResolver | Нет долгоживущего состояния | Имя и метаданные видео | Выбор даты и основы имени | Распознавание ходов, запись JSON |
| ParseManager | Текущий источник и отчёт | Результат resolver | Передача имён экспорту, диагностика | Разбор дат |
| ExportStorage | Временный файл записи | JSON на диске | Прежняя атомарная запись | Выбор даты, перезапись |

## Impact

Новый resolver использует уже установленный PyAV и стандартный datetime.
Затрагиваются manager, фикстуры имён в тестах, README. Контракт содержимого JSON,
параметры CLI и распознавание игры сохраняются. Архивирование предыдущего изменения
input-output-directories должно завершиться перед реализацией этого изменения.
